회차01 웹의 구성 요소
  1. 인터넷장현규
  2. 웹김유진
  3. 브라우저김수민
  4. HTML변진수
  • 개발 PC와 JBoss 서버가 사내망에서 통신하지만 인터넷은 끊겨 있습니다. 네트워크는 연결됐지만 인터넷은 아니라고 말할 수 있는 기준은 무엇인가요?
  • 인터넷이 끊겨도 http://localhost의 Vue 3 화면은 열립니다. 인터넷 없이 웹을 사용할 수 있는 이유를 접속 범위와 HTTP 기준으로 설명해 보세요.
  • 같은 eXBuilder 화면 파일을 공유 폴더에서 연 경우와 Apache 주소로 연 경우가 있습니다. 파일 내용이 같아도 한쪽만 웹 요청이 되는 이유는 무엇인가요?
  • Vue 3 주소 하나를 입력했는데 Apache에 HTML·CSS·JavaScript 요청이 따로 전송됩니다. 브라우저가 화면을 한 파일로 받지 않는 이유는 무엇인가요?
  • JBoss 연결이 끊긴 뒤에도 eXBuilder 화면의 모양은 남아 있지만 조회는 실패합니다. 브라우저가 이미 가진 파일과 새로 받아야 할 데이터를 구분해 보세요.
  • Vue 3 버튼을 눌렀는데 네트워크 요청 없이 화면만 바뀌었습니다. 브라우저가 JavaScript와 DOM으로 처리했다고 판단할 근거는 무엇인가요?
  • 같은 HTML을 file://과 https://로 열면 상대 경로와 보안 규칙이 달라집니다. 브라우저가 두 문서의 출처를 다르게 보는 이유는 무엇인가요?
  • eXBuilder 개발 도구에서 만든 화면은 사용자의 브라우저에서 실행됩니다. 개발 도구와 실행 결과물을 같은 프로그램이라고 부르면 무엇이 헷갈리나요?
  • HTML·CSS는 보이지만 eGovFrame 조회만 실패합니다. 브라우저, Apache, JBoss 중 어디까지 정상이라고 판단할 수 있고 어디부터는 아직 알 수 없나요?
  • 사용자가 Vue 3에서 조회한 결과가 Tibero에서 돌아왔습니다. 웹·브라우저·HTML이 이 흐름에서 각각 맡은 일을 구분해 보세요.
회차02 웹 애플리케이션의 역할
  1. 클라이언트장현규
  2. 서버김유진
  3. 프론트엔드김수민
  4. 백엔드변진수
  • Vue 3와 eXBuilder는 프론트엔드이면서 eGovFrame API의 클라이언트입니다. 프론트엔드와 클라이언트가 항상 같은 뜻은 아닌 이유는 무엇인가요?
  • 모바일 앱도 eGovFrame API를 호출할 수 있습니다. 이 앱은 클라이언트이지만 Vue 3나 eXBuilder 프론트엔드는 아닌 이유를 설명해 보세요.
  • Apache는 화면 파일을 보내고 요청을 JBoss로 전달합니다. 서버 프로그램인 Apache를 업무 백엔드와 구분해야 하는 이유는 무엇인가요?
  • JBoss는 eGovFrame 애플리케이션을 실행합니다. 두 기술을 모두 백엔드라고만 부르면 실행 환경과 업무 코드의 책임이 어떻게 섞이나요?
  • Tibero가 설치된 장비, 실행 중인 DBMS, 그 안의 데이터베이스는 모두 DB 서버라고 불리기도 합니다. 장애 위치를 말할 때 셋을 구분해야 하는 이유는 무엇인가요?
  • eXBuilder 화면은 브라우저에서, eGovFrame 코드는 JBoss에서 실행됩니다. 요청을 보내는 쪽과 업무를 처리하는 쪽을 각각 어떻게 분류하나요?
  • Vue 3에서 계산한 금액을 eGovFrame이 다시 검증합니다. 프론트엔드 계산을 그대로 믿으면 데이터가 조작될 수 있는 이유는 무엇인가요?
  • 한 번의 조회가 브라우저 → Apache → JBoss의 eGovFrame → Tibero로 이어집니다. 각 구성 요소를 클라이언트와 서버 역할로 짝지어 보세요.
  • Apache의 화면 파일은 열리지만 조회 데이터가 나오지 않습니다. 프론트엔드 표시 성공과 백엔드 처리 성공을 같은 결과로 볼 수 없는 이유는 무엇인가요?
  • 브라우저 요청, Apache 전달, eGovFrame 처리, Tibero 조회 중 하나가 실패했습니다. 각 단계의 기록을 어떤 순서로 확인해야 실패 구간을 좁힐 수 있나요?
회차03 네트워크 연결
  1. IP김수민
  2. DNS장현규
  3. 포트변진수
  4. TCP/UDP김유진
  • Vue 3의 조회는 브라우저 → Apache → JBoss → Tibero로 이어집니다. 각 구간의 출발지·목적지 IP를 구분해 보세요.
  • localhost로 둔 eGovFrame API가 JBoss 서버에서는 되고 eXBuilder PC에서는 안 됩니다. 두 환경의 localhost는 어디인가요?
  • DNS가 도메인을 Apache IP로 바꿨습니다. JBoss의 eGovFrame과 Tibero까지 찾은 것은 아닌 이유는 무엇인가요?
  • Apache를 새 IP로 옮기자 Vue 3는 새 서버, eXBuilder는 이전 서버로 갑니다. DNS 응답과 TTL로 원인을 어떻게 가리나요?
  • Apache는 443, JBoss는 8080, Tibero는 8629를 씁니다. 각 포트의 접속 주체와 목적지를 짝지어 보세요.
  • 외부에는 Apache의 443만 열려 있습니다. JBoss의 8080과 Tibero의 8629가 막혀도 브라우저에서 조회할 수 있는 이유를 전체 통신 경로로 설명해 보세요.
  • Apache는 JBoss의 8180으로 보내지만 JBoss는 8080에서 듣습니다. 어느 연결이 왜 실패하나요?
  • DNS용 UDP는 성공하지만 Apache 443의 TCP 연결은 시간 초과됩니다. 각 결과가 확인해 준 범위는 어디까지인가요?
  • 조회 한 번에 브라우저–Apache, Apache–JBoss, JBoss–Tibero가 통신합니다. 왜 하나의 TCP 연결로 이어지지 않나요?
  • JBoss가 eGovFrame의 HTTP 500을 보냈습니다. 어느 TCP 구간까지 성공했으며 Tibero 처리는 왜 단정할 수 없나요?
회차04 HTTP
  1. URL과 리소스
  2. 메서드와 멱등성
  3. 상태 코드와 메시지
  4. HTTP 캐시
  • 같은 도메인의 /assets/app.js는 Apache가 보내고 /api/users는 JBoss로 전달합니다. URL이 어느 리소스와 처리 대상을 가리키는지 어떻게 구분하나요?
  • 목록 URL의 페이지 번호만 바뀌는 경우와 사용자 번호가 경로에 들어가는 경우가 있습니다. 쿼리와 경로가 각각 어떤 대상을 표현해야 하나요?
  • GET 조회를 반복하자 로그는 늘었지만 Tibero 데이터는 바뀌지 않았습니다. 안전성과 멱등성을 로그 생성 여부로 판단하면 안 되는 이유는 무엇인가요?
  • 같은 POST 저장이 두 번 도착했습니다. Vue 3의 중복 클릭 방지, 요청 고유 번호, Tibero 고유 키는 각각 어느 단계에서 중복을 막나요?
  • Apache가 POST 요청을 새 URL로 보냅니다. 302 대신 307이나 308을 써야 원래 메서드와 본문이 유지되는 이유는 무엇인가요?
  • 404, 405, 502는 각각 리소스, 메서드, Apache–JBoss 연결 중 어디에서 문제가 생겼다는 뜻인가요?
  • HTTP 200인데 eXBuilder는 저장 실패를 표시합니다. 전송 성공과 eGovFrame 업무 결과를 상태 코드와 응답 본문으로 어떻게 나눠 판단하나요?
  • Apache가 504를 보낸 뒤에도 JBoss가 Tibero 저장을 끝낼 수 있습니다. 브라우저의 시간 초과와 서버 작업 종료를 같은 사건으로 볼 수 없는 이유는 무엇인가요?
  • 브라우저가 ETag를 보내자 Apache가 304로 답했습니다. 응답 본문이 없어도 화면 파일을 사용할 수 있는 이유는 무엇인가요?
  • 배포 뒤 일부 사용자만 예전 Vue 3 화면을 봅니다. Apache의 새 파일과 브라우저 캐시 중 어느 쪽을 확인해야 하는지 ETag와 파일명으로 판단해 보세요.
회차05 HTML
  1. 문서 구조
  2. 콘텐츠 모델
  3. 시맨틱과 접근성
  4. 폼과 데이터
  • Vue 3 화면에서 h1보다 p를 더 크게 꾸몄습니다. 글자 크기가 아니라 HTML 구조로 문서의 대표 제목을 판단해야 하는 이유는 무엇인가요?
  • HTML에서 html, head, body를 생략했는데 DOM에는 생겼습니다. 브라우저 파서가 문서 구조를 보정하는 기준은 무엇인가요?
  • p 안에 div를 넣자 원본과 DOM의 부모·자식 관계가 달라졌습니다. 콘텐츠 모델을 어긴 태그를 브라우저가 어떻게 처리한 결과인가요?
  • eXBuilder가 만든 요소를 div로 바꾸고 클릭만 연결하면 button과 같아지나요? 키보드 동작과 기본 의미까지 비교해 보세요.
  • Vue 3의 조건부 렌더링으로 제목을 만들었습니다. 화면에 보였다 사라져도 h1부터 h6까지의 순서를 지켜야 하는 이유는 무엇인가요?
  • 조회 표에 td만 있고 th가 없습니다. 화면 모양은 같아도 스크린 리더가 열 제목과 값을 연결하지 못하는 이유는 무엇인가요?
  • 입력 칸 옆에 ‘이름’이라는 글자만 놓았습니다. label을 input과 연결했을 때 마우스·키보드·스크린 리더 동작이 어떻게 달라지나요?
  • eXBuilder 입력 화면에서 Enter를 누르자 저장 요청이 전송됐습니다. 버튼 코드가 없어도 HTML 폼의 기본 제출이 실행될 수 있는 이유는 무엇인가요?
  • input에 값이 보이지만 name이 없거나 disabled입니다. 브라우저가 폼 데이터에서 이 값을 제외하는 기준은 무엇인가요?
  • Vue 3에서 필수 입력을 검사했지만 API를 직접 호출하면 우회할 수 있습니다. HTML 검증과 eGovFrame 검증이 각각 필요한 이유는 무엇인가요?
회차06 CSS 적용 원리
  1. 캐스케이드
  2. 명시도와 상속
  3. 박스 모델
  4. 문서 흐름과 display
  • Vue 3의 공통 CSS를 나중에 불러왔는데도 컴포넌트 스타일이 남았습니다. 선언 순서만으로 캐스케이드 결과를 정할 수 없는 이유는 무엇인가요?
  • 같은 요소에 인라인 스타일, ID, 클래스, !important가 적용됐습니다. 출처·중요도·명시도·순서는 어떤 차례로 최종 값을 정하나요?
  • 부모의 글자색은 자식에게 이어지지만 너비는 이어지지 않습니다. CSS 속성마다 상속 여부가 다른 이유와 inherit의 역할은 무엇인가요?
  • eXBuilder가 만든 클래스와 공통 CSS의 클래스 이름이 같습니다. 선택자 명시도와 로드 순서를 함께 봐야 실제 스타일을 찾을 수 있는 이유는 무엇인가요?
  • width: 100%인 영역에 padding과 border를 주자 부모보다 커졌습니다. 기본 박스 모델에서 실제 너비는 어떻게 계산되나요?
  • box-sizing: border-box를 적용하자 같은 width에서도 내용 영역이 줄었습니다. padding과 border가 어느 범위 안에 들어간 결과인가요?
  • 개발자 도구에는 새 CSS가 보이지만 화면 크기는 그대로입니다. 계산된 값과 취소선 규칙으로 박스 크기를 결정한 선언을 어떻게 찾나요?
  • span에 너비와 높이를 줘도 반영되지 않습니다. inline, inline-block, block의 크기와 줄바꿈 규칙을 비교해 보세요.
  • display: none과 visibility: hidden은 모두 보이지 않습니다. 레이아웃 공간과 접근성 트리에는 어떤 차이가 생기나요?
  • Vue 3의 v-if와 v-show로 같은 영역을 숨겼습니다. DOM 제거와 display 변경은 다시 표시할 때 어떤 차이를 만들까요?
회차07 CSS 레이아웃
  1. Flexbox
  2. Grid
  3. Position과 Stacking Context
  4. 반응형 디자인
  • Vue 3의 버튼 묶음은 한 줄, 대시보드는 행과 열을 함께 맞춰야 합니다. Flexbox와 Grid를 각각 선택할 기준은 무엇인가요?
  • Flex 자식의 긴 텍스트가 영역 밖으로 밀려납니다. flex-basis, 축소 비율, min-width: 0이 최종 너비에 어떻게 관여하나요?
  • 카드 수를 알 수 없는 Vue 3 목록에 repeat(auto-fit, minmax(...))를 썼습니다. 화면 폭에 따라 열 수가 자동으로 바뀌는 원리는 무엇인가요?
  • Grid에 배치 위치를 지정하지 않은 카드가 새 행에 생겼습니다. 명시적 격자와 자동으로 만들어진 암시적 격자는 어떻게 다른가요?
  • eXBuilder 팝업에 position: absolute를 주자 아래 영역이 위로 당겨졌습니다. 문서 흐름에서 빠진 요소의 자리는 어떻게 계산되나요?
  • 팝업에 z-index: 9999를 줘도 다른 영역 뒤에 가립니다. 자식의 숫자보다 부모가 만든 Stacking Context를 먼저 비교해야 하는 이유는 무엇인가요?
  • fixed 헤더와 sticky 헤더는 스크롤할 때 비슷해 보입니다. 위치 기준과 원래 자리 유지 방식은 어떻게 다른가요?
  • 고정 좌표로 만든 eXBuilder 화면이 작은 모니터에서 잘립니다. 요소보다 부모의 고정 너비와 viewport를 먼저 확인해야 하는 이유는 무엇인가요?
  • 같은 모니터에서도 브라우저 확대율을 바꾸자 미디어 쿼리가 달라졌습니다. CSS 픽셀과 실제 화면 픽셀이 일치하지 않는 이유는 무엇인가요?
  • 카드 목록을 Flex 줄바꿈과 Grid 반응형 열로 각각 만들 수 있습니다. 자식 크기와 행·열 정렬을 누가 결정하는지 비교해 보세요.

  • 프로그램 파일은 이전 버전으로 되돌렸지만 Tibero 테이블 구조는 이미 새 버전에 맞게 바뀌었습니다. 프로그램 파일만 되돌려서는 복구되지 않을 수 있는 이유는 무엇인가요?

  • Vue 화면에서 클라우드 AI를 바로 호출하면 비밀 접속 키(API 키)가 브라우저에 드러날 수 있습니다. 요청을 eGovFrame과 WildFly가 대신 보내게 하면 키를 숨길 수 있는 이유는 무엇인가요?
  • eGovFrame과 WildFly가 클라우드 AI에 질문을 보내고 답을 받는 과정도, 다른 서버 API처럼 HTTP 요청과 응답으로 이루어진다고 볼 수 있는 이유는 무엇인가요?
  • 내 PC의 localhost:11434에서 Ollama가 실행됩니다. localhost는 ‘현재 사용 중인 내 컴퓨터’를 뜻하므로 다른 팀원의 PC에서는 같은 주소로 접속할 수 없는 이유는 무엇인가요?
  • 클라우드 AI만 응답하지 않는다면 인터넷 연결·접속 키·외부 서비스 상태를 확인해야 하고 Ollama만 응답하지 않는다면 내 PC의 프로그램 실행 여부와 포트를 확인해야 합니다. 확인 대상이 다른 이유는 무엇인가요?
  • 없는 eGovFrame API 필드 이름을 생성형 AI가 자연스럽게 적어 줬습니다. 문장이 매끄럽다는 것만으로 그 필드가 존재한다고 보면 안 되는 이유는 무엇인가요?
  • 이전 대화와 소스 파일을 계속 붙여 넣었더니 처음 준 WildFly 로그가 답에 반영되지 않습니다. 한 번에 넣을 수 있는 토큰 수와 컨텍스트 창이 꽉 차면 무엇이 잘리나요?
