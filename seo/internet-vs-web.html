웹 기초 개념

인터넷은 길이고 웹은 그 길을 이용하는 서비스입니다

인터넷과 웹은 자주 같은 뜻으로 쓰이지만 기술적으로는 범위가 다릅니다. 이 차이를 알면 브라우저, 서버, DNS, HTTP를 따로 외우지 않고 하나의 요청 과정으로 연결할 수 있습니다.

인터넷은 여러 네트워크를 연결하는 기반

인터넷은 서로 다른 네트워크가 공통 규칙을 사용해 데이터를 주고받도록 연결한 전 세계적인 통신 기반입니다. 데이터는 작은 단위로 나뉘어 여러 장비와 경로를 지나 목적지에 도착합니다. 이 기반 위에서는 웹뿐 아니라 이메일, 파일 전송, 원격 접속, 음성 통화 같은 여러 서비스가 동작합니다.

따라서 브라우저를 닫아도 인터넷 자체가 사라지는 것은 아닙니다. 메일 앱이 메시지를 동기화하거나 게임이 서버와 통신하는 동안에도 같은 네트워크 기반을 이용하고 있습니다.

웹은 URL과 HTTP, 문서로 연결된 정보 공간

월드 와이드 웹은 인터넷을 이용해 문서와 자원을 주고받는 서비스입니다. 브라우저는 URL로 위치를 표현하고 HTTP 또는 HTTPS로 서버에 요청을 보냅니다. 서버가 돌려준 HTML은 문서 구조를, CSS는 표현을, JavaScript는 상호작용을 맡는 경우가 많습니다.

웹의 핵심은 링크입니다. 한 문서가 다른 문서의 주소를 가리키면서 정보가 연결됩니다. 검색엔진도 공개된 링크와 사이트맵을 따라 페이지를 발견하고, 문서의 제목과 본문, 구조화된 정보를 바탕으로 내용을 이해합니다.

주소를 입력하면 먼저 목적지를 찾습니다

브라우저 주소창에 도메인을 입력하면 컴퓨터는 먼저 그 이름에 대응하는 서버 주소를 알아내야 합니다. DNS는 사람이 읽기 쉬운 도메인 이름을 통신에 사용할 주소와 연결하는 역할을 합니다. 브라우저나 운영체제에 최근 결과가 남아 있다면 이 조회 과정은 생략되거나 짧아질 수 있습니다.

목적지를 확인한 뒤에는 서버와 통신할 연결을 준비합니다. HTTPS라면 암호화 통신에 사용할 상대와 인증서를 확인하고 안전한 세션을 협상합니다. 이 과정은 사용자가 보낸 내용이 이동 중에 그대로 노출되거나 바뀌는 위험을 줄입니다.

요청과 응답은 정해진 형식으로 오갑니다

연결이 준비되면 브라우저는 원하는 경로와 가능한 응답 형식, 쿠키 같은 정보를 담아 HTTP 요청을 보냅니다. 서버는 요청을 처리한 뒤 상태 코드, 콘텐츠 형식, 캐시 지침과 함께 본문을 돌려줍니다. 200은 일반적인 성공 응답이고, 301은 다른 주소로의 영구 이동, 404는 요청한 자원을 찾지 못했다는 뜻입니다.

  1. 도메인을 서버 주소로 확인
  2. 서버와 연결하고 HTTPS 보안 협상
  3. 경로와 헤더를 담은 HTTP 요청 전송
  4. 상태 코드와 HTML 응답 수신
  5. 추가 CSS, JavaScript, 이미지 요청

브라우저가 받은 파일을 화면으로 조립합니다

브라우저는 HTML을 읽어 문서 구조를 만들고 CSS 규칙을 적용해 각 요소의 크기와 위치를 계산합니다. 필요한 JavaScript를 실행하고 이미지나 글꼴을 불러온 뒤 화면에 픽셀을 그립니다. 스크립트가 문서 읽기를 오래 막거나 큰 이미지가 늦게 도착하면 사용자가 첫 화면을 보는 시간도 길어집니다.

개발자 도구의 네트워크 패널을 열면 이 과정을 직접 확인할 수 있습니다. 어떤 요청이 먼저 시작됐는지, 상태 코드는 무엇인지, 응답 크기와 대기 시간이 어느 정도인지 보면 “웹페이지가 느리다”는 현상을 네트워크, 서버, 파일 처리 단계로 나누어 볼 수 있습니다.

개념을 구분하면 장애 원인도 좁혀집니다

다른 인터넷 서비스는 되는데 특정 웹사이트만 열리지 않는다면 인터넷 연결 전체보다 DNS, 해당 서버, 인증서, 브라우저 캐시를 먼저 의심할 수 있습니다. 반대로 여러 앱과 사이트가 모두 통신하지 못한다면 장치의 네트워크 연결이나 공유기, 통신사 구간을 확인해야 합니다.

인터넷과 웹의 차이는 시험용 정의에 그치지 않습니다. 요청이 어느 층에서 막혔는지를 판단하는 기준이며, 프런트엔드와 백엔드, 네트워크가 하나의 사용자 경험으로 이어지는 출발점입니다.

함께 보면 좋은 안내

네트워크 역사 연표패킷 교환과 인터넷 프로토콜이 발전한 흐름을 시대순으로 확인하세요.웹 개발 역사 연표초기 웹 문서부터 현대 웹 애플리케이션까지 이어지는 변화를 살펴보세요.IT 역사 공부 순서컴퓨터, 네트워크, 운영체제, 데이터베이스와 웹을 연결해 공부하는 순서입니다.

주소 입력부터 화면 표시까지의 흐름을 연표 속 기술과 연결해 보세요.
